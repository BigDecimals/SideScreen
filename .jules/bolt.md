## 2024-05-24 - Zero-Allocation Network Loops in Android
**Learning:** High-frequency event loops like touch streaming can generate significant GC pressure if they allocate buffers per-event. `StreamClient` in `AndroidClient` uses a single-threaded executor (`touchScope`), meaning we can safely share a single pre-allocated `ByteBuffer` across all serialization calls (touch, ping) without locks, completely eliminating GC overhead in the hot path. Similarly, primitive stream reads combined with zero-allocation transformations (`java.lang.Long.reverseBytes()`) completely eliminate the need for temporary `ByteArray` allocations when parsing responses.
**Action:** When optimizing network loops (especially real-time/streaming), check if the underlying dispatcher is single-threaded. If it is, immediately replace per-event allocations with a reused instance variable buffer. Replace wrap/buffer reads with primitive bitwise operations where possible.
